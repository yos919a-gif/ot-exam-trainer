# OTトレーナーのPC UI改善

対象はホーム・過去問・暗記カード・結果・用語入力。幅1024px以上でPC向けの配置にし、従来のスマホ表示を保つ。

## 確認した問題

基準は用語入力60問版 `f44f310`。PCの本文幅が1040pxに固定され、ホームの用語入力を含む暗記・復習は上端約1639pxにあった。1280×720では、過去問採点後の結果ボタンは上端1186px、用語入力の採点後の次問は上端1107pxで、いずれもスクロールが必要だった。

## 変更

- ホーム：上限幅1320px。進捗と今日の復習を横並びにし、上部に用語入力・過去問50問・今日の暗記カードの開始操作をまとめた。模試3カードとROM／範囲条件の配置を整理した。
- 過去問：1280px以上では問題・画像と選択肢を2列にした。1024pxでは読みやすい幅の1列を保つ。採点・次問の操作バーをPCでもstickyにし、長文の先頭・途中・末尾から操作できるようにした。
- 暗記・結果：読み幅と操作位置を揃え、主要操作を追いやすくした。
- 用語入力：開始条件と中断・前回の記録を横並びにした。出題中は問題と入力を横並び、採点後は問題・選択した答えと解説・次問を2列で表示する。
- 低いPC画面：候補8件を開いた場合も、候補内をスクロールし、解答・答えを見る・中断のボタンを画面内に保つ。
- キーボード：PCの細かいポインター環境では開始・次問時に入力へフォーカスする。上下キーで候補を選び、Enterで選択／解答、採点後のEnterで次問へ。IME変換・長押し・修飾キーやリンク、出典の開閉、ボタン本来の操作を妨げない。
- 上部バー：共通の色トークンを保ち、PC時だけ幅・高さ・間隔を整理した。最新基点の「語の網」を含む5タブと、スマホのタブ内横スクロールを維持。画面のキャッシュは最新基点のv14からv15へ更新。

## 検査と成果物

`tools/pc_ui_check.cjs` と `docs/PC_UI確認/` に、変更前後の画像・数値・操作検査を保存する。基準の生ソース複製 `.baseline/` と作業用バックアップはローカル検査用であり、PRの提出対象に含めない。

確認対象は1024×768、1280×720、1440×900、1920×1080、スマホ360/390/412px、暗色。全体の表示・操作120項目、用語入力の追加操作36項目、ホーム最終調整の差分10項目、開始ボタン位置4項目の計170項目に合格。ページの横はみ出し、主操作の画面内可視性とクリック、採点・誤り理由・結果、候補のキーボード操作、旧記録・過去問記録の保持を確認した。最後のホーム調整は3つの統計を1行に揃えた変更で、PC4幅の画像と計測を更新し、全体検査は繰り返していない。

医学データ・問題数・採点判定・保存形式・同期処理は従来のものを利用する。`content/` と医学問題3データファイルに差分がないことを確認。実利用者の学習記録を読み書きせず、独立したブラウザーと模擬APIで検査した。

## 提出範囲

UIの変更は `feature/desktop-ui` に分けた。60問の用語入力機能のPR #1（`feature/term-input-practice`）を基点とする別PRで、公開版への反映はレビュー・マージ後。

提出時に基点の更新を検出したため、PC変更の1コミットだけを新基点 `46acfda` へ移した。旧履歴のmergeは行わず、新しい `ami.html`、5タブ、教科書側の追加などは最新基点のまま保持した。変更前画像と170項目の検査は元の `f44f310` 基準として残し、最新基点との統合確認は別の検査記録に区別する。

統合後は追加44項目に合格。PC4幅・スマホ3幅で5タブとページの横はみ出し、スマホの末尾タブへのスクロール、PCの「語の網」往復、用語入力と過去問の操作を確認した。SHELLのv15・ami登録・各ローカルファイルの存在は静的確認であり、実際のService Workerインストールの検査とは区別する。

Android実機、スクリーンリーダー、実ネット配信・Service Workerの圏外動作は未確認。
