# スマホ UI 設計（発注01）

対象: Android Chrome、縦向き・横幅360 / 390 / 412px。PCは1280pxで確認する。
問題・正答・採点方式・復習間隔・辞書本文は変更しない。既存の色トークンを使用し、CDNやライブラリを追加しない。

## 調査と方針

修正前の実表示は `スマホUI確認/before/` に保存する。優先度はP0（毎問の操作を妨げる）、P1（読みやすさ・誤タップ）、P2（補助画面の改善）。

| 画面 | 優先度 | 問題点 | 直し方 |

| ホーム | P1 | 大きな進捗リングと余白で、日々の操作が下方になる | スマホの進捗カードを横組みにして小さくする。今日やることへ早く到達できる高さにする |
| 演習中の問題 | P0 | 操作部が問題カード末尾のstickyなので、長い問題では初期表示から届かない。しおり・用語操作は30px | スマホのみ下部固定操作バー。主操作を下段いっぱいにし、副操作を上段へ。本文末尾にバー高さ以上の余白を設ける。しおり等は44px |

## 実装基準

- スマホ専用の指定は原則640px以下。PCの構成・色・主な余白は維持する。
- タップ操作は最低44px、隣り合う操作は原則8pxの余白（ナビゲーションは枠で区別）。
- 問題文17px・選択肢16pxの既存指定は維持し、誤り理由・辞書本文も16pxにする。
- 固定バーはsafe-area-inset-bottomを加算し、本文やメモを隠さない余白を設ける。
- ページ全体をoverflow:hiddenで隠して解決しない。長い文字は折返し、幅が必要な表と図だけ独立スクロールにする。
- 新しい操作には名前とキーボードフォーカスを用意する。ダイアログは閉じたときに元の図へフォーカスを戻す。

## 確認方法

独立したヘッドレスChromeのブラウザコンテキストで実表示する。`/api/load/` と `/api/save/` は模擬応答し、利用者の学習記録を読まず、保存しない。各対象画面を4幅で修正前後に撮影する。ページ全体の横はみ出し・操作サイズ・コンソールエラーを記録し、演習1問の選択→採点→誤り理由→結果、用語・図・暗記カードの操作を確認する。追加で暗色表示と低い画面で固定バーを確認する。

結果と残課題は `スマホUI確認/README.md` に記録する。

## 実装結果

上表のP0〜P2を実装した。スマホの上部バーは実測109pxから65pxへ縮小。演習バーは117pxで主操作48px、副操作44px。暗記の評価は54px。4幅のページ全体の横はみ出しは0、スマホ3幅の撮影状態では44px未満の通常操作は0だった（図・表の内部スクロールは意図したもの）。

独立レビューで、下端から次問へ進むと前問のスクロール位置が残る事象を確認したため、新しい問題・カードの表示時に先頭へ戻すよう修正した。採点後とカードの裏返し時は読んでいる位置を維持する。360×480、640×360、1280×900でクリックして再検証済み。

問題データ、医学的な説明文、`judge`、得点計算、復習間隔は変更していない。`SHELL_CACHE` は `ot-shell-v8` から `ot-shell-v9` に更新した。新しいアプリ配信ファイルはないため、`SHELL` の項目追加は不要。

Android実機のソフトキーボード・OSジェスチャー領域・ピンチ操作は未確認。実機での片手の押しやすさと合わせて最終検品する。
