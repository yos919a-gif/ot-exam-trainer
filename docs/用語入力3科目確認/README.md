## データ検査前の操作抑止：追加11項目

用語集のHTTP取得が成功しても、内容が`{}`のような不正スキーマの場合を追加した。エラーを表示して開始を無効にし、その後どの科目へ切り替えてフォーム送信しても問題画面へ進まず、練習記録も作らないことを確認。正常な用語集へ戻して再読み込みすると、通常の5問セッションを開始し、採点と次問へ進めることも確認した。

基礎502項目の`report.json`を上書きせず、追加11項目だけを`report-invalid-schema.json`に保存した。今回の変更はデータ検査成功前の操作抑止だけなので、基礎検証全体の繰り返し実行はしていない。追加検証だけを実行する場合は、環境変数`TERM_CHECK_MODE=invalid-schema`を指定する。通常実行時にはこの追加経路も検証対象に含まれる。

## 実施方法と限界

`node tools/term_input_check.cjs`で実行する。ローカルの作業ファイルをブラウザーのリクエストへ直接返し、APIも模擬応答にした。実際の利用者の学習記録は読み書きしていない。API保存2回は既存過去問確認時の模擬保存。

実Android端末のソフトキーボード・IME、スクリーンリーダー、実ネット配信とService Workerの圏外動作は未確認。根拠リンクの検査は必須メタデータとHTTPS形式の検査であり、医学的な内容・引用先の検品は別途行う。
